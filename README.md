# nix-narinfo

`nix-narinfo` parses, validates, verifies, and canonically writes the metadata
records used by Nix binary caches. It is pure Rust and does not link to Nix.

## What it implements

| Area | Supported features |
| --- | --- |
| Parsing | A 1 MiB input limit, UTF-8 and line validation, required and singleton fields, repeated signatures, and forward-compatible extension preservation. |
| Identity | Shared `StoreDir`, `StorePath`, `NixHash`, and `CAHash` types from [`nix-derivation`](https://crates.io/crates/nix-derivation). |
| Serialization | Deterministic Nix field order, canonical hash and content-address encodings, sorted references, and store-aware absolute paths. |
| Signatures | Typed Ed25519 public keys, signature decoding and verification, and the exact Nix binary-cache fingerprint. |
| Content addressing | Pure reconstruction of flat, recursive NAR, text, and Git content-addressed store paths, including references and self-references. |
| Construction | A builder that keeps fields private and rejects values that cannot be serialized and reparsed without changing structure. |

Here, canonical means that a value always serializes to one standard sequence
of bytes. Parsing an alternate logical store retains that directory, so a
`/gnu/store` record remains a `/gnu/store` record when written again.

## Deliberate boundaries

This crate does not perform HTTP requests, select cache URLs, download or
decompress NARs, ingest archives, order substituters, configure trust, convert
to an application-specific `PathInfo`, or mutate a store. In
particular, it deliberately does not depend on `nix-archive`: callers may use
any NAR implementation after narinfo validation has selected the expected hash
and size.

Signature verification answers a cryptographic question only. Callers decide
whether signatures are required and which users or caches are trusted.

## Parsing and verification

```rust
use nix_derivation::StoreDir;
use nix_narinfo::{NarInfo, TrustedPublicKey};

fn inspect(record: &[u8], encoded_keys: &[&str])
    -> Result<(), Box<dyn std::error::Error>>
{
    let store_dir = StoreDir::default();
    let info = NarInfo::parse_in(&store_dir, record)?;
    let keys = encoded_keys
        .iter()
        .map(|key| TrustedPublicKey::parse(key))
        .collect::<Result<Vec<_>, _>>()?;

    println!("{}", info.fingerprint(&store_dir));
    println!("signed: {}", info.has_valid_signature(&store_dir, &keys));
    println!("content-addressed: {}", info.is_content_addressed(&store_dir));
    Ok(())
}
```

`NarInfo` also implements `FromStr` as a convenience for records in the
conventional `/nix/store`. Use `parse_in` whenever the logical store directory
is configurable.

## Constructing records

```rust
use nix_derivation::{NixHash, StoreDir, StorePath};
use nix_narinfo::{Compression, NarInfo};

let store_dir = StoreDir::new("/gnu/store")?;
let path = StorePath::from_basename(
    b"00000000000000000000000000000000-example",
)?;
let info = NarInfo::builder_in(
    store_dir,
    path,
    "nar/example.nar.zst",
    NixHash::Sha256([1; 32]),
    4096,
)
.compression(Compression::Zstd)
.file_size(Some(1024))
.build()?;

let bytes = info.to_canonical_bytes();
# Ok::<(), Box<dyn std::error::Error>>(())
```

## Compatibility and tests

The field syntax and cache fingerprint follow Nix 2.34. The offline test corpus
contains a `.narinfo` generated by Nix 2.34.7, a known Ed25519 cache-signature
vector, alternate-store cases, every supported content-address method, parser
limits, malformed input, and canonical round trips.

An optional differential test checks every `.narinfo` in a Nix-created
`file://` cache:

```console
NIX_NARINFO_PARITY_DIR=/path/to/cache cargo test --test nix_parity
```

The fuzz target is independent of feature flags:

```console
cargo fuzz run parse
```

Run the dependency-free parser benchmark with:

```console
cargo bench --bench parse
```
